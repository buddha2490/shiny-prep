# Plotly Reference App

A comprehensive Shiny + Plotly reference application built around a 10-million-row GWAS dataset. Each tab demonstrates a distinct set of plotly patterns for future reuse.

## Quick Start

```r
shiny::runApp("examples/02. plotly")
```

Requires: `shiny`, `bslib`, `data.table`, `plotly`, `ggplot2`, `scales`, `viridisLite`. Optional: `shinycssloaders` (for loading spinners).

## Data

`gwas_data.csv` — 10M simulated GWAS SNPs across 23 chromosomes. Generated by `generate_gwas_data.R`. Three columns: `chr`, `pos`, `pvalue`.

## Tab 1: Manhattan Plot (`R/mod_manhattan.R`)

The core large-data scatter plot. Demonstrates the fundamental patterns for plotting large datasets with plotly in Shiny.

### Patterns

| Pattern | What it does | Where in code |
|---------|-------------|---------------|
| **`scattergl`** | WebGL-accelerated scatter (GPU rendering). Essential for >10K points. Use `type = "scattergl"` instead of `type = "scatter"`. | `add_trace(..., type = "scattergl")` |
| **Downsampling** | Keep all significant SNPs, randomly thin non-significant. Controlled by a slider. | `plot_data` reactive |
| **Custom hover text** | HTML-formatted hover with `<b>`, `<br>`, formatted numbers. Pass as `text` aesthetic + `hoverinfo = "text"`. | `hover_text` column |
| **Shapes** | Horizontal threshold lines via `layout(shapes = ...)`. Use helper `make_hline()`. | Threshold lines section |
| **Annotations** | Arrow-pointed labels on top hits via `layout(annotations = ...)`. Supports `bgcolor`, `bordercolor`, `borderpad`. | Top hit annotations |
| **`plotly_selected`** | Box/lasso selection event. Returns a data frame of selected points' `x`, `y` values. Used to drive a detail zoom panel. | `zoom_plot` output |
| **`plotly_click`** | Single-point click event. Returns `x`, `y`, `curveNumber`, `pointNumber`. Used to populate an info card. | `click_info` output |
| **Range slider** | `rangeslider()` adds a minimap below the x-axis for quick navigation. | End of plot pipeline |
| **Config** | `config()` customizes the mode bar: add/remove buttons, set export format/filename/dimensions, enable scroll zoom. | `config(...)` call |
| **`source`** | `plot_ly(source = "id")` + `event_data(..., source = "id")` links events to specific plots when multiple plotly outputs exist. | Source parameter |
| **Empty guards** | Check `nrow(d) == 0` before plotting. Return `empty_plot("message")` placeholder. | Top of renderPlotly |
| **Loading spinner** | `withSpinner_safe()` wraps plotlyOutput with a spinner (falls back gracefully). | UI wrapper |
| **Data download** | `downloadHandler()` exports the filtered/downsampled data as CSV. | `download_data` handler |

### When to use these patterns

- **Any scatter plot with >10K points** → use `scattergl`
- **Any dataset where you need reference lines** → use `shapes` + `make_hline()`
- **Any plot where users need to drill into a region** → use `plotly_selected` + detail panel
- **Any plot where click = action** → use `plotly_click`

## Tab 2: Proxy Updates (`R/mod_proxy.R`)

Demonstrates `plotlyProxy()` — the single most important pattern for production plotly apps. Updates plots WITHOUT full re-render.

### Patterns

| Pattern | What it does | Where in code |
|---------|-------------|---------------|
| **`plotlyProxy()`** | Creates a proxy reference to an existing plotly widget. All subsequent updates go through this proxy. | `proxy <- plotlyProxy("id", session)` |
| **`restyle`** | Update trace properties (marker size, color, opacity) on existing traces. Trace indices are 0-based. | `apply_restyle` observer |
| **`relayout`** | Update layout properties (axis ranges, titles, shapes, annotations). | `apply_zoom` and `apply_shapes` observers |
| **`addTraces` / `deleteTraces`** | Add or remove entire traces. Used for the secondary y-axis overlay. | `show_cumulative` observer |
| **Click-to-annotate** | Accumulate annotations in a `reactiveVal(list())`, push all via `relayout(annotations = ...)`. | `click_annotate` flow |
| **`updatemenus`** | Built-in buttons rendered into the plot chrome. Call `restyle` or `relayout` directly in the browser — zero server involvement. | Log/linear scale toggle |
| **Secondary y-axis** | `yaxis2 = list(overlaying = "y", side = "right")` creates a right-side axis. Traces target it with `yaxis = "y2"`. | Cumulative distribution overlay |

### When to use proxy

- **Changing colors, sizes, opacity** → `restyle` (not re-render)
- **Zooming to a specific range** → `relayout` with `xaxis.range`
- **Adding/removing threshold lines** → `relayout` with `shapes`
- **Adding annotations interactively** → `relayout` with `annotations`
- **Toggling a secondary data series** → `addTraces` / `deleteTraces`
- **Client-side toggles** → `updatemenus` (no server at all)

### When NOT to use proxy

- **Changing the underlying data entirely** → full re-render is cleaner
- **First render** → must use `renderPlotly()` initially

## Tab 3: ggplotly Conversion (`R/mod_ggplotly.R`)

Demonstrates building plots in ggplot2 and converting to plotly. Shows common pitfalls and cleanup steps.

### Patterns

| Pattern | What it does | Where in code |
|---------|-------------|---------------|
| **`ggplotly(p, tooltip = "text")`** | Convert ggplot2 to plotly. The `tooltip` arg controls which aesthetics appear in hover — use `"text"` and map a custom `text` aesthetic. | Main QQ plot |
| **Tooltip control** | Map `text = paste0(...)` in `aes()` to build custom hover. Without `tooltip = "text"`, ggplotly shows ALL mapped aesthetics. | `aes(text = ...)` |
| **Legend fix** | ggplotly renders legend titles as `<br>variable`. Fix with `layout(legend = list(title = list(text = "...")))`. | Layout cleanup |
| **`style(hoverinfo = "skip")`** | Disable hover on specific traces (e.g., confidence bands). Trace index is 1-based in R. | Ribbon trace skip |
| **`geom_ribbon()` → `add_ribbons()`** | ggplot2 ribbon geoms convert to plotly ribbon traces. Used for confidence intervals. | 95% CI band |
| **Continuous color scale** | `scale_color_viridis_c()` in ggplot2 becomes a plotly `colorbar`. Shows `colorscale`, `cmin`, `cmax` equivalent. | Color by -log10(p) option |
| **`theme_plotly_clean()`** | Custom ggplot2 theme that matches the plotly house style. Use before conversion so styles are consistent. | Theme application |
| **Raw vs cleaned comparison** | Toggle to see side-by-side what ggplotly produces by default vs after cleanup. | Comparison panel |

### When to use ggplotly vs plot_ly

| Use ggplotly when... | Use plot_ly when... |
|---------------------|---------------------|
| You already have a ggplot2 workflow | You need scattergl (WebGL) |
| You need facets (`facet_wrap`/`facet_grid`) | You need fine-grained trace control |
| You want static PDF + interactive HTML from same code | You have >50K points |
| The plot is simple (scatter, line, bar, box) | You need advanced events or proxy updates |

### ggplotly cleanup checklist

1. Set `tooltip = c("text")` and map custom `text` aesthetic
2. Fix legend title: `layout(legend = list(title = list(text = "...")))`
3. Skip hover on annotation traces: `style(hoverinfo = "skip", traces = N)`
4. Use `theme_plotly_clean()` so ggplot2 and plotly styles match
5. Test hover on EVERY trace — ggplotly can produce unexpected hover content

## Tab 4: Linked Views / Crosstalk (`R/mod_linked.R`)

Demonstrates client-side linked brushing across multiple panels using crosstalk.

### Patterns

| Pattern | What it does | Where in code |
|---------|-------------|---------------|
| **`highlight_key(df, ~key)`** | Wraps a data frame in a `SharedData` object. The key column identifies selectable units. | `sd <- highlight_key(d, ~row_id)` |
| **`subplot()`** | Combines multiple plotly objects into a single widget. Controls: `nrows`, `shareX`, `shareY`, `widths`, `margin`. | 3-panel layout |
| **`highlight()`** | Configures selection behavior on SharedData plots. Key args: `on`, `off`, `persistent`, `opacityDim`, `selected`. | Highlight config |
| **`attrs_selected()`** | Defines visual attributes applied to selected points (marker size, color, opacity). | Selected point styling |
| **Persistent vs transient** | `persistent = TRUE`: click to add to selection, double-click to clear. `persistent = FALSE`: hover to highlight, mouseout to clear. | Radio button toggle |
| **Client-side only** | All brushing happens in the browser via crosstalk. No server round-trip = instant response. | Architecture note |

### Crosstalk limitations

- Does NOT work with `scattergl` — must use `scatter` (SVG)
- All data sent to browser — keep under ~20K points
- Only works with plotly, DT, and leaflet
- Cannot do server-side filtering (no reactive involvement)

## Tab 5: Semantic Zoom / LOD (`R/mod_semantic_zoom.R`)

The most advanced performance pattern. Dynamically adjusts data resolution based on the current viewport.

### Patterns

| Pattern | What it does | Where in code |
|---------|-------------|---------------|
| **`plotly_relayout`** | Fires when the user zooms or pans. Returns `xaxis.range[0]`, `xaxis.range[1]` (current viewport bounds). Also fires `xaxis.autorange = TRUE` on reset. | Main observer |
| **Viewport query** | Use the x-axis range to filter the full 10M-row dataset with data.table: `gwas[bp_cum >= x_min & bp_cum <= x_max]`. | Region filtering |
| **Adaptive downsampling** | If the region has more points than `max_points`, downsample. If fewer, show full resolution. | Conditional logic |
| **Binned aggregation** | Alternative to random downsampling: divide x-axis into N bins, keep the most significant SNP per bin. Never drops important signals. | `binned` mode |
| **Proxy data swap** | Delete all traces via `deleteTraces`, then `addTraces` with new data. Avoids full re-render. | Trace replacement |
| **Status display** | Show users the current resolution: points in range, points rendered, percentage. Builds trust in the visualization. | Status outputs |

### When to use semantic zoom

- Datasets with >1M points where global downsampling loses too much
- Exploratory tools where users need to drill into specific regions
- Any plot where "zoom in for detail" is a natural interaction

## Utility Helpers (`R/utils_plotly_theme.R`)

Reusable functions shared across all tabs.

| Function | Purpose |
|----------|---------|
| `apply_plotly_theme(p)` | Apply house style (colors, fonts, margins, hover, config) to any plot_ly or ggplotly object. Modify this ONE function to restyle all plots. |
| `make_hline(y, color, width, dash)` | Create a horizontal line shape for `layout(shapes = ...)`. |
| `make_hline_label(y, text, color)` | Create a text annotation for a threshold line. |
| `empty_plot(message)` | Return a blank plotly widget with a centered message. Use for empty states. |
| `theme_plotly_clean(base_size)` | ggplot2 theme that matches the plotly house style. Use before `ggplotly()` conversion. |

## Architecture Notes

### File structure

```
examples/02. plotly/
  global.R                    # packages, data loading, pre-computation
  ui.R                        # page_navbar with 5 tabs
  server.R                    # module server calls only
  R/
    utils_plotly_theme.R      # reusable theme + helper functions
    mod_manhattan.R           # Tab 1: core scatter patterns
    mod_proxy.R               # Tab 2: plotlyProxy patterns
    mod_ggplotly.R            # Tab 3: ggplot2 conversion patterns
    mod_linked.R              # Tab 4: crosstalk/linked brushing
    mod_semantic_zoom.R       # Tab 5: LOD rendering
  generate_gwas_data.R        # script to regenerate the test data
  gwas_data.csv               # 10M-row GWAS dataset
```

### Performance decision tree

```
How many points?
  ├── <1K     → scatter (SVG) is fine, use ggplotly if convenient
  ├── 1K-20K  → scatter (SVG) works, crosstalk/linked views OK
  ├── 20K-100K → use scattergl (WebGL), downsample if needed
  ├── 100K-1M  → scattergl + aggressive downsampling, use proxy for updates
  └── >1M     → scattergl + semantic zoom (LOD), binned aggregation
```

### Key plotly.js concepts

- **Traces** are individual data series (one per `add_trace`). Indexed 0-based in JS, 1-based in R.
- **Layout** controls axes, shapes, annotations, margins, background. Shared across all traces.
- **Config** controls the toolbar, export, and interaction modes. Set once.
- **`source`** parameter on `plot_ly()` + `event_data(source = ...)` links events to specific widgets (critical when multiple plotly outputs exist in one app).
- **`customdata`** carries arbitrary data through to click/hover/select events without displaying it.
